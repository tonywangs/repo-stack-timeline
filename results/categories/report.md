# Annual project categories and declared stacks

Exploratory appendix to the eight-repository 2019–2025 [dependency study](../annual/report.md).

Categories measure annual package self-descriptions with disclosed keyword rules, chosen after inspecting the cohort. They are not independent human labels, a validated classifier, or evidence of GitHub-wide category prevalence. Ambiguous or unmatched descriptions are unknown. Each row retains the exact description and immutable source link.

Observed category changes: **0/48** comparable adjacent-year repository pairs; 0 pairs have unknown categories. A stable label does not prove stable functionality.

All 8/8 members were selected from surviving projects at acquisition; 4/8 share Pallets governance. This design includes zero deleted/inaccessible repositories and zero applications. Survival probability and GitHub-wide category coverage cannot be estimated from this sample. Fixed membership makes category shares insensitive to projects entering or leaving GitHub. Unknown runtime metadata remains unknown even when a category is measurable.

## Reproduce

`python3 scripts/category_report.py --check` verifies source objects and byte-identical results. `python3 scripts/category_report.py --output /tmp/annual-categories` creates fresh Markdown and JSON. The JSON includes rule expressions, source hashes, annual declared names, and all zero-member cells. The original acquisition and missing-data rules remain in [the source documentation](../../examples/annual/README.md).

This checkpoint adds category evidence to the existing convenience sample. A broader study of changing project types still needs a defined sampling frame that includes applications, entry/exit, and independent governance. Do not treat this appendix as answering those population questions.
