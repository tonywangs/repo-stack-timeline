# Applications alongside the library cohort

A bounded 2019–2025 public-data extension. Two application cases supplement the eight-library study; the comparison below uses only its four JavaScript libraries. No GitHub-wide estimates are made.

## Findings

Of 14 application snapshots, 10 have observable root declarations; 4 are unknown. Counts and changes below concern only that root scope.

## Design and limits

Prospectively frozen two-member application extension before annual extraction. Purposeful maximum-contrast cases: Node-RED visual event-driven programming and Etherpad collaborative document editing, from separate owner namespaces outside Pallets. Public primary repository descriptions inspected 2026-10-24. Chosen for end-user application purpose and JavaScript comparability with the existing library cohort, not observed dependency trajectories. This is a convenience case study, not a probability sample or an estimate of independent governance.

Application purpose was used to select cases before extracting annual manifests. These current selection strata must not be interpreted as annual labels: the exact annual descriptions below are evidence for inspection, not a validated project-type classifier. Neither separate owner names nor these two cases establish statistical independence of governance.

Both added cases (2/2) are surviving public projects at acquisition. Together with the prior study, 10/10 cases are selected survivors; 4/10 share Pallets governance. There are zero sampled deleted or inaccessible projects. Inclusion probabilities, survival probabilities, entry/exit rates and coverage of all GitHub project categories remain unidentifiable. This expansion does not repair population sampling.

Root runtime declarations omit nested application packages, plugins, optional and development dependencies. An observed zero means zero required names in that root manifest, not a dependency-free application. A missing root manifest is unknown. Root structure changes can therefore dominate apparent stack changes.

## Reproduce and inspect

`python3 scripts/application_report.py --check` verifies preserved Git objects and all report artifacts. `python3 scripts/application_report.py --output /tmp/application-report` creates a fresh report. Open `index.html` locally or inspect `report.json` for declarations and coverage denominators. See [source documentation](../../examples/applications/README.md) for acquisition and licenses.
