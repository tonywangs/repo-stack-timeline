# JSON report v1

The top-level object has these fields:

| Field | Meaning |
| --- | --- |
| `schema_version` | Literal `repo-stack-timeline/1` |
| `semantics_version` | Literal `declarations/1`; rules in semantics.md |
| `object_format` | `sha1` or `sha256` |
| `selection_order` | Literal `as_supplied` |
| `scope` | Human-readable interpretation warning |
| `limits` | All configured resource limits |
| `counts` | Actual aggregate tree-entry, manifest-candidate and manifest-byte counts |
| `snapshots` | Ordered selected snapshots, including repeats |
| `comparisons` | One record per adjacent selected pair; no baseline events |

A snapshot contains `index` (zero-based), immutable `commit` and `tree` IDs,
`parents` in commit-header order, `committer_time` (`unix`, original `offset`, or
null), `manifests`, and snapshot-level `diagnostics`.

A manifest contains `path`, `blob`, `mode`, `ecosystem` (`npm` or `python`),
`status` (`ok`, `partial`, `invalid`, `unsupported`), `uncertain_all`,
`uncertain_categories`, `declarations`, and `diagnostics`.
A diagnostic has a stable `code`, optional `category`, and optional context such
as `name`, `group`, `declaration`, or `path`. Categories ending `.*` express
uncertainty for the namespace; this is not a general glob language.

A declaration contains `category`, identity `name`, and `values`. Each value has
an exact string `raw` and `name_as_declared`. Python values additionally have
`extras` (array), `specifier` (string), `marker` (string or null), and `url`
(string or null). Multiple values are a sorted multiset, preserving duplicates.

A comparison has `before_index`, `after_index`, `ancestry`, `diagnostics` and
`events`. Each event has `kind` (`added`, `absent`, `changed`, `unknown`), the
identity fields `path`, `ecosystem`, `category`, `name`, and `before`/`after`
(value arrays or null). `before_commit`/`after_commit` identify the selected
snapshots; `before_blob`/`after_blob` identify the corresponding path when present,
including malformed manifests. Missing paths have a null blob.

Consumer rules:

1. Reject unknown schema/semantics versions rather than assuming compatibility.
2. Preserve strings, including surrogate-escaped non-UTF-8 Git paths.
3. Inspect coverage diagnostics; an empty event list is not a completeness claim.
4. `null` for an `unknown` side is not proof of dependency absence.
5. Do not sort snapshots by time or treat ancestry as an inferred selection order.
6. JSON is evidence data, never executable markup. Paths and URLs are not safe to
   open automatically or use as filesystem write targets.

Examples can be generated with `python3 scripts/demo.py /tmp/stack-demo`.
This schema is descriptive; arbitrary imported JSON is not accepted by the CLI.
The viewer embeds only reports generated by this version, rather than promising
a general-purpose parser for unknown report data.
